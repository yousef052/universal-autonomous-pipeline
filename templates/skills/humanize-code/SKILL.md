# Humanize Code: Expert Software Engineering Craftsmanship & Intuition

This skill guides AI agents in stripping away the telltale artifacts of generic language model generation. It instills the craftsmanship, pragmatic simplicity, and architectural taste of a seasoned **Staff / Principal Software Engineer**.

When applied, code ceases to look like a textbook or a junior tutorial. Instead, it reads like clean, deliberate literature written by an engineer who has maintained production systems for a decade.

### Pillar 1: Elimination of AI Tells & Robotic Code Smells

AI models have distinct statistical habits that scream *"generated by a machine"*. This skill mandates their active elimination:

1. **The Parrot Comment Smell (KILL ON SIGHT):**
   - ❌ *AI Smell:*
     ```typescript
     // Check if user is null
     if (!user) {
       // Return false
       return false;
     }
     ```
   - ✅ *Human Craft:* Delete the comments entirely. The code already says this.
2. **The Redundant Staging Variable Smell:**
   - ❌ *AI Smell:*
     ```typescript
     const calculatedTotal = computeTotal(items);
     return calculatedTotal;
     ```
   - ✅ *Human Craft:*
     ```typescript
     return computeTotal(items);
     ```
3. **Generic Filler Naming (BANNED):**
   - ❌ *Forbidden words:* `data`, `item`, `temp`, `res`, `val`, `obj`, `handleData()`, `processItems()`, `HelperManagerService`.
   - ✅ *Contextual names:* `unreconciledTransfers`, `activeSession`, `payoutCadence`, `isEligibleForTierDiscount`.
4. **Premature Enterprise FizzBuzz (Anti-Overengineering):**
   - ❌ *AI Smell:* Creating `IUserValidationStrategyFactoryProvider` for a function used in one place.
   - ✅ *Human Craft:* Write a clean, private, pure helper function. Introduce interfaces only when there are multiple polymorphic implementations or external boundaries requiring testing mocks.
5. **Parroting Docstrings:**
   - ❌ *AI Smell:*
     ```csharp
     /// <summary>
     /// Gets the order by identifier.
     /// </summary>
     /// <param name="id">The identifier.</param>
     /// <returns>The order.</returns>
     public Order GetOrderById(Guid id)
     ```
   - ✅ *Human Craft:* Omit docstrings that add zero informational entropy. Use docstrings only to document side effects, invariants, performance characteristics, or expected exceptions.

### Pillar 2: High-Signal Rationale Comments (The "WHY, Not WHAT" Law)

A human expert only writes a comment when the code cannot explain itself. Comments exist to explain:
- **Business Logic Context:** Why this strange business rule exists.
- **Upstream Vendor Quirks & Workarounds:** Compensating for third-party bugs.
- **Intentional Performance Trade-offs:** Why an un-intuitive algorithm was selected.
- **Safety Invariants:** Why something that looks refactorable must stay untouched.

#### Examples of Human-Grade Comments:
```typescript
// NOTE: Stripe API v2024 returns null on zero-fee invoices instead of 0.
const feeAmount = invoice.fee ?? 0;

// HACK: Safari on iOS ignores 'overflow: hidden' when a child has 'transform: translateZ(0)'.
// Adding 'isolation: isolate' forces a separate stacking context.
const modalStyles = "isolation-auto overflow-hidden";

// We deliberately bypass the change tracker here. On a 100k-row batch,
// EF Core tracking consumes ~450MB of heap and causes noticeable GC pauses.
var entries = await context.LedgerEntries
    .AsNoTracking()
    .Where(x => x.BatchId == batchId)
    .ToListAsync(ct);
```

### Pillar 3: Domain Storytelling & Semantic Naming

Code should read like high-fidelity prose describing the business domain.

#### Naming Conventions for Human Intuition:
- **Booleans:** Must read like grammatical predicates answering a yes/no question:
  - ✅ `isAvailable`, `hasGracePeriodExpired`, `canRefundTransaction`, `shouldRetryOnFailure`.
  - ❌ `checkValid`, `flag`, `status`, `successBool`.
- **Collections:** Use natural plural nouns reflecting the domain entity:
  - ✅ `pendingInvoices`, `settledLedgerEntries`, `whitelistedOrigins`.
  - ❌ `invoiceList`, `arrayData`, `dataMap`, `itemsList`.
- **Actions:** Use precise domain verbs:
  - ✅ `reconcile()`, `revoke()`, `disburse()`, `supersede()`, `evict()`.
  - ❌ `doAction()`, `process()`, `handle()`, `updateStuff()`.

### Pillar 4: Early Exits & The Flat Guard Clause Aesthetic

Human experts hate the **Arrowhead Anti-Pattern** (deep pyramid indentation caused by nested `if/else`).

#### ❌ AI-Generated Deep Nesting:
```csharp
public Result<Receipt> ProcessRefund(RefundRequest request)
{
    if (request != null)
    {
        if (request.Amount > 0)
        {
            var order = _orderRepo.Find(request.OrderId);
            if (order != null)
            {
                if (order.IsPaid)
                {
                    // Core logic buried 5 levels deep
                    return Result.Success(ExecuteRefund(order, request.Amount));
                }
                else
                {
                    return Result.Failure("Order is not paid");
                }
            }
            else
            {
                return Result.Failure("Order not found");
            }
        }
        else
        {
            return Result.Failure("Amount must be positive");
        }
    }
    return Result.Failure("Request is null");
}
```

#### ✅ Senior Human Guard Clause Architecture:
```csharp
public Result<Receipt> ProcessRefund(RefundRequest request)
{
    ArgumentNullException.ThrowIfNull(request);

    if (request.Amount <= 0)
        return Result.Failure("Refund amount must be strictly positive.");

    var order = _orderRepo.Find(request.OrderId);
    if (order is null)
        return Result.Failure($"Order '{request.OrderId}' was not found.");

    if (!order.IsPaid)
        return Result.Failure($"Order '{order.Id}' cannot be refunded because its status is '{order.Status}'.");

    // The happy path stays flat against the left margin:
    var receipt = ExecuteRefund(order, request.Amount);
    return Result.Success(receipt);
}
```

### Pillar 5: Idiomatic Fluency & Modern Ergonomics

Expert engineers embrace modern language features naturally, rather than translating 2008 Java syntax into TypeScript or C#.

#### Modern Idioms to Use by Default:
| Language | ❌ Outdated / AI Robotic Syntax | ✅ Senior Human Idiomatic Syntax |
| :--- | :--- | :--- |
| **C#** | `public class Person { public string Name { get; set; } }` | `public sealed record Person(string Name);` |
| **C#** | `new List<string>() { "a", "b" }` | `["a", "b"]` (Collection expressions) |
| **C#** | `if (user != null && user.Address != null)` | `if (user is { Address: not null })` |
| **TS** | `type State = { loading: boolean, error?: string, data?: T }` | `type State = { status: 'idle' } \| { status: 'loading' } \| { status: 'success'; data: T }` |
| **TS** | `(x: any) => x as User` | Type predicates: `(x: unknown): x is User => ...` |
| **Python** | `result = []` loop with `append` | List comprehension or generator expressions |

### Pillar 6: Operational Empathy & Human-Centric Error Messages

When an exception is thrown in production at 3:15 AM, the on-call engineer needs immediate answers from the log message without firing up a debugger:
- **What happened?**
- **What value was passed?**
- **What was expected?**
- **What was the entity ID?**

#### ❌ AI Generic Error:
```typescript
throw new Error("Invalid transfer amount.");
```

#### ✅ Human Operational Empathy:
```typescript
throw new InvalidTransferException(
  `Transfer amount must be positive. Received '${amount}' for account '${accountId}'.`
);
```

#### ❌ AI Cryptic 500:
```csharp
catch (Exception ex)
{
    _logger.LogError(ex, "An error occurred");
    return StatusCode(500, "Internal Server Error");
}
```

#### ✅ Human Structured Diagnostic:
```csharp
catch (PaymentGatewayTimeoutException ex)
{
    _logger.LogWarning(ex, 
        "Payment gateway timed out during charge for Order {OrderId} after {ElapsedMs}ms. Initiating idempotency reconciliation.",
        orderId, stopwatch.ElapsedMilliseconds);
    
    return Problem(
        statusCode: StatusCodes.Status504GatewayTimeout,
        title: "Payment Gateway Unresponsive",
        detail: "The upstream payment processor did not respond in time. Your account was not charged.");
}
```

### Pillar 7: Visual Rhythm, Vertical Breathing & Grouping

Code should have a pleasant optical density. It should read in logical paragraphs:
1. **Inputs & Guard Clauses** (Top paragraph)
2. *[blank line]*
3. **Core Computation / Orchestration** (Middle paragraph)
4. *[blank line]*
5. **Persistence / Side Effects** (Lower paragraph)
6. *[blank line]*
7. **Return / Presentation** (Final line)

Never place a blank line after every single statement (AI stuttering), nor pack 80 lines together without a single breath.

## 🔬 Head-to-Head Comparison: Before vs After

### Real-World Challenge: User Profile Update & Notification

#### ❌ Before: Standard AI Output (Robotic, Noisy, Over-engineered)
```typescript
// UserService.ts
import { UserRepository } from './UserRepository';
import { EmailService } from './EmailService';
import { User } from './User';

export class UserService {
    private userRepository: UserRepository;
    private emailService: EmailService;

    // Constructor to inject dependencies
    constructor(userRepository: UserRepository, emailService: EmailService) {
        this.userRepository = userRepository;
        this.emailService = emailService;
    }

    // Function to update the user email
    public async updateUserEmail(userId: string, newEmail: string): Promise<User | null> {
        try {
            // Find the user by id
            const user = await this.userRepository.findById(userId);

            // Check if user exists
            if (user != null) {
                // Check if email is valid
                const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
                if (emailRegex.test(newEmail)) {
                    // Update user email
                    user.email = newEmail;
                    // Save user
                    const updatedUser = await this.userRepository.save(user);
                    // Send notification email
                    await this.emailService.sendEmail(newEmail, "Email updated", "Your email has been updated successfully.");
                    // Return updated user
                    return updatedUser;
                } else {
                    console.log("Invalid email format");
                    return null;
                }
            } else {
                console.log("User not found");
                return null;
            }
        } catch (error) {
            // Catch error
            console.error("An error occurred", error);
            return null;
        }
    }
}
```

#### ✅ After: Humanized Senior Craftsmanship
```typescript
import { z } from 'zod';
import { Result } from '@/shared/result';
import type { UserRepository, NotificationService, User } from '@/domain/types';

const EmailSchema = z.string().trim().email('Invalid email address format.');

export class UserService {
    constructor(
        private readonly users: UserRepository,
        private readonly notifications: NotificationService
    ) {}

    public async updateEmail(userId: string, rawEmail: string): Promise<Result<User>> {
        const emailResult = EmailSchema.safeParse(rawEmail);
        if (!emailResult.success) {
            return Result.fail(emailResult.error.issues[0]?.message ?? 'Invalid email');
        }
        const validatedEmail = emailResult.data;

        const user = await this.users.findById(userId);
        if (!user) {
            return Result.fail(`User [${userId}] was not found.`);
        }

        if (user.email === validatedEmail) {
            return Result.ok(user); // Idempotent: no update needed
        }

        user.changeEmail(validatedEmail);
        const updatedUser = await this.users.save(user);

        // Fire-and-forget notification: delivery failure should not roll back email change
        this.notifications.sendEmailChangedAlert(updatedUser.id, validatedEmail).catch((err) => {
            console.warn(`Failed to dispatch email change alert to User [${userId}]:`, err);
        });

        return Result.ok(updatedUser);
    }
}
```

## 📋 The 10-Point Humanize Audit Checklist

Before finalizing any generated code, apply this rapid 10-point audit:

1. [ ] **Zero Parrot Comments:** Did you delete all comments that merely repeat what the next line of code says?
2. [ ] **High-Signal "WHY" Only:** Do remaining comments explain business justification, vendor workarounds, or performance caveats?
3. [ ] **No Generic Naming:** Did you replace `data`, `res`, `item`, `temp`, `helper` with domain terms?
4. [ ] **Flat Left Margin:** Are guard clauses used to exit early instead of nesting 3+ levels deep?
5. [ ] **Direct Returns:** Did you remove useless temporary variables created just before a `return` statement?
6. [ ] **Empathetic Errors:** Do error messages specify the faulty value, entity identifier, and actionable remediation context?
7. [ ] **Modern Language Idioms:** Does the code leverage modern syntax (records, collection expressions, pattern matching, discriminated unions)?
8. [ ] **No Premature Abstractions:** Is there an unnecessary interface or factory that can be simplified into a clean function?
9. [ ] **Proper Vertical Rhythm:** Are related statements grouped into paragraphs with single blank lines separating logical phases?
10. [ ] **Idempotency & Edge-Case Consciousness:** Does the code handle "no-op" cases gracefully (e.g. updating a value to what it already is)?
